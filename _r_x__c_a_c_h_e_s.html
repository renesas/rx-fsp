RX Caches
Note
This overview should be considered supplementary information only. Consult with the listed references (non-exhaustive) for detailed information on the Renesas caches, and cache coherency. Cache coherency can be a difficult problem to understand and solve correctly.

Overview

When using any type of caches in a system, coherency must be considered. A cache may contain data that is different from the backing memory (e.g. SRAM, Flash, etc.), or contain data that is different from another cache, which would make the cache incoherent. Coherency can be maintained through hardware and/or software support.

RX Cache Features

Please refer to the RX Hardware User Manuals for details on the caching feature.

Cache Functions and Macros

Renesas BSP Configuration Macros

Macro Purpose Notes
BSP_CFG_DCACHE_ENABLED Defaults to 0 (disabled). If defined and set to a non-zero value, the FSP startup code in system.c enables the MPU and configures the D-Cache for the XSPI0 CS0/1, XSPI1 CS0/1, SDRAM, Code MRAM, and Internal RAM regions. This is normally configured in e2 studio under the BSP->Cache settings->Data cache properties panel for the project.
BSP_CFG_ICACHE_ENABLED Defaults to 0 (disabled). If defined and set to a non-zero value, the FSP startup code in system.c enables the MPU and configures the I-Cache for the XSPI0 CS0/1, XSPI1 CS0/1, SDRAM, Code MRAM, and Internal RAM regions. This is normally configured in e2 studio under the BSP->Cache settings->Instruction cache properties panel for the project.

Note on Cache Coherency

Software is required to guarantee coherency between the caches and external memory or on-chip SRAM. When multiple bus masters (for example, the CPU and DMAC) share an area in the scope of a cache, flush and write back the cache contents as required.
